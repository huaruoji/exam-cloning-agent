# Exam Cloner 答辩讲稿

## 使用说明

这版按 12 分钟准备。前半段讲清楚问题和方案，约 4 分钟完整演示，最后留一点时间做切换和应变。

如果现场只给 10 分钟，删掉第 7、8 页的细节，把第 12 页工程数据压缩成一句话。核心演示不要删。

演示时不要追求把每个页面都点一遍。评委只需要看到一条完整路径。

载入演示课程 → 查看算力中心 → 做客观题 → 批改主观题 → 故障切换演练 → 回 Dashboard 看下一步学习。

讲稿里的“停”表示给评委看屏幕，不需要继续说话。数字和延迟以现场页面为准，不要死背截图里的数值。

## 逐页讲稿

### 第 1 页｜开场

大家好，我们是香港科技大学（广州）的王语诺和刘睿淇。

今天介绍 Exam Cloner。它把课程材料整理成题库，再根据学生的答题情况安排练习和复习。我们重点解决一个实际问题。模型服务不稳定时，备考流程还能不能继续。

停一下，让评委先看到项目名称和主题。

### 第 2 页｜先讲清产品怎么工作

使用 Exam Cloner 时，学生先上传试卷、作业和课件。系统从材料里整理出题目、知识点和考试风格，接着生成练习或模拟卷。学生答题后得到反馈，错题会回到下一轮复习里。

底部这条回流线很重要。答题结果会影响下一次练习，学生做完一套题之后还会得到下一步安排。

这里还有一个资源判断。能在本地完成的事情，就不调用模型；确实需要模型时，再去找可用的模型服务。

### 第 3 页｜为什么要做

备考过程中有三个很常见的卡点。

第一，材料很多，但题目和知识点分散在不同文件里。第二，刷题之后常常只得到一个对错，学生不知道自己漏了哪一步。第三，大模型服务会遇到限流、超时，或者部署环境根本没有 GPU。

所以我们真正想解决的问题很直接。资源有波动时，学生还能不能稳定地练下去。

### 第 4 页｜整体方案

这页可以把它理解成四块拼在一起。

左边负责把材料变成结构化题库，中间是 Exam Cloner 的学习流程，右边根据记忆情况安排复习，下面的资源路由负责决定每一步应该走哪种处理方式。

这里的“自适应复习”听起来很复杂，其实就是系统记住每个知识点最近答得怎么样，再决定什么时候重新出现。学习功能和资源调度在同一条链路里，所以模型暂时不可用时，客观题和已有题库仍然可以工作。

### 第 5 页｜系统架构

前端是学生看到的学习工作台，后端负责课程、题目和答题记录。中间的模型路由会根据任务选择处理方式。

这里的模型路由可以理解成一个分流器。它先看任务能不能用规则完成，再看题库里有没有现成结果，最后才把请求交给模型服务。没有可用模型时，系统会明确标记“未批改”，不会把一次服务故障算成学生答错。

我们当前部署在单进程环境里，使用 JSON 做轻量存储。这个选择适合比赛演示和小规模课程，不把它包装成已经解决了大规模生产部署。

### 第 6 页｜资源路由

这页是项目和算力网最直接的连接。

路由顺序从上到下，先处理成本最低、最稳定的路径。选择题和判断题有标准答案时，本地就能判定；题库里已经有的题目也直接复用。只有这些路径不够用时，系统才会尝试用户配置的模型服务、管理员配置的本地服务，或者内置模型。

每个模型服务都有超时、并发限制和熔断保护。熔断可以理解成保险丝。一个服务连续失败三次，系统会暂时停止向它发请求，过一段时间再探测。

如果所有服务都不可用，系统返回未批改。学生可以稍后重试，掌握度不会被错误更新。

### 第 7 页｜SM-2 用人话解释

这一页的 SM-2 不需要展开公式。它是一种安排复习间隔的方法。核心想法很简单，刚答错的知识点早点回来，连续答对的知识点可以隔久一点再出现。

每次答题后，系统会更新这个知识点的掌握情况和难度系数。下一次练习优先选择已经到期、又比较薄弱的知识点。

这样，练习顺序来自学生自己的答题记录，每个人的下一道题都可能不同。客观题可以立即给反馈，主观题才按需调用模型。

### 第 8 页｜考试风格和批改

系统会从原试卷中整理题型、难度和主题，再放入几道参考题，让生成的新题尽量贴近这门课原来的出题方式。

批改也不只给一个分数。对于简答、计算和论述题，系统会指出缺少的步骤、错误的知识点，并给出下一步建议。选择题、判断题仍然优先使用本地规则。

所以这里的“克隆”是模仿考试风格，系统不会复制原题。“深度批改”会告诉学生怎样改，也会解释具体问题在哪里。

### 第 9 页｜算力中心截图

现在进入算力中心。

停，给评委看左侧的模型服务状态，再看右侧的最近路由记录。

这里的每条记录都来自实际请求或探测，包括服务状态、延迟、成功或失败，以及节省了多少模型调用。这个页面把路由过程直接展示出来，评委可以现场检查。

如果现场显示本地服务不可用，不要回避。可以直接说，当前容器没有可用的本地模型，所以系统显示降级状态。这也说明了兜底路径正在发挥作用。

### 第 10 页｜Dashboard 截图

回到 Dashboard。

停，指一下推荐的下一步、题库数量和薄弱主题。

学生不需要自己翻日志判断该做什么。系统把材料、题库、薄弱点和下一次练习放在一个页面里。算力中心记录的是资源情况，Dashboard 呈现的是学习结果，两边通过答题记录连起来。

### 第 11 页｜现场演示主线

这一页只按下面的顺序操作，不要临场自由发挥。

#### 1. 载入演示课程

点击 Demo，确认课程和题库已经出现。

口头说，先加载一门准备好的课程，避免把时间花在等待上传和解析上。真实上传流程已经实现，但现场重点看学习和资源调度。

#### 2. 查看算力中心

点击 Compute。

口头说，先看当前有哪些模型服务可用，再看系统当前处于正常还是降级模式。

#### 3. 做一道客观题

回到 Practice，选择一道选择题或判断题，提交答案。

口头说，这类题有确定答案，系统在本地完成判定，不需要调用模型。演示后回到 Compute，看路由记录和节省次数是否变化。

停两秒，让评委看到这次请求没有走模型服务。

#### 4. 批改一道主观题

选择简答题、计算题或论述题，输入一段准备好的答案并提交。

口头说，这类题需要理解过程，系统会选择健康的模型服务，并返回结构化反馈。重点看三个地方，使用了哪个服务、用了多长时间、反馈里有没有缺失步骤和错误知识点。

如果现场模型服务不可用，就展示“未批改”或备用服务状态，说明系统没有把服务故障误判成答题错误。

#### 5. 跑故障切换演练

点击 Run failover drill。

口头说，这个按钮是无成本的模拟演练，不会发送真实课程答案。它用测试内容模拟服务失败，让我们看到系统如何选择下一条路径。这里的 drill 是演示故障处理，不会破坏线上服务。

#### 6. 回 Dashboard

回到 Overview，看推荐练习和薄弱主题。

口头收束，到这里，一次答题已经影响了路由记录、学习状态和下一次练习。整个过程就是项目的核心闭环。

### 第 12 页｜工程和边界

最后补充工程部分。

我们覆盖了用户隔离、提交幂等、错题导出、原子写入、文件名检查和请求地址安全检查。SSRF 防护可以简单理解为一条限制，用户填写的模型地址不能借机访问服务器内网。

当前部署环境没有验收 GPU，所以页面会明确显示硬件状态待验收。我们保留了 GPU 和本地模型的接入位置，但不把没有测过的硬件性能写成结果。

### 第 13 页｜总结

Exam Cloner 有三个重点。

第一，先用规则和题库减少不必要的模型调用。第二，根据学生的答题记录安排后续复习。第三，把服务状态、路由结果和学习结果都展示出来。

它先服务好一门课程和一次真实演示，再为更多模型和更多算力平台留下扩展空间。

我们的介绍到这里，谢谢各位老师，欢迎提问和现场演示。

说完停下，不要继续补充。把时间留给评委。

## 术语小抄

| 术语 | 现场说法 |
| --- | --- |
| SM-2 | 一种按答题表现安排复习间隔的方法。答错早点复习，答对后逐渐拉长间隔。 |
| 模型路由 | 一个分流器，根据任务和服务状态决定请求交给谁处理。 |
| provider | 模型服务，也就是可以接收生成或批改请求的端点。 |
| fallback | 当前服务失败后，切换到下一条备用路径。 |
| 熔断器 | 一个服务连续失败后暂时停止请求，避免继续浪费时间和费用。 |
| 结构化反馈 | 按固定字段返回结果，例如缺失步骤、错误知识点和改进建议。 |
| 风格克隆 | 学习原试卷的题型、难度和表达方式，再生成相近的新题。 |
| SSRF 防护 | 防止用户提供的地址借服务器访问内网或内部服务。 |
| 题库复用 | 已有题目或结果可以直接使用，减少重复生成。 |
| 降级 | 模型服务不可用时保留可用功能，并明确告诉用户哪些内容暂时没有批改。 |

## 可能的评委提问

### 1. 你们为什么把它算作算力网应用？

我们没有把算力网只理解成“接一张 GPU”。系统会根据任务，把请求分到本地规则、题库、用户模型服务、管理员本地服务和内置模型。它还会记录服务状态、延迟、失败和切换结果。这个调度过程直接影响学生能不能继续学习。

### 2. 你们现在真的用了 GPU 吗？

当前部署容器没有经过验收的 GPU，所以我们没有虚构 GPU 利用率。系统通过 HTTP 接入兼容的模型服务，并保留了本地 GPU 服务的接入位置。页面会把当前状态写成硬件待验收。

### 3. 没有 GPU 时，你们的系统还能做什么？

课程管理、材料管理、题库浏览、选择题和判断题判定、已有题目复用、学习记录和复习调度都可以继续。需要模型的主观题会显示未批改，或者在有备用服务时自动切换。

### 4. SM-2 和简单的错题本有什么区别？

错题本只告诉我们哪些题错过。SM-2 还会根据连续答对情况调整复习间隔，并在知识点层面安排下一次出现时间。它轻量、可解释，适合当前这个课程备考场景。

### 5. 考试风格克隆会不会只是换几个词？

我们会先从试卷中整理题型、难度和主题，再把参考题放进生成上下文。模拟卷还支持调整题型、难度和题库与新题的比例。它模仿的是出题习惯，不承诺复制原题。

### 6. 模型批改错了怎么办？

系统把规则题和主观题分开处理。规则题有确定答案时本地判定；主观题的结果会保留结构化反馈。如果模型调用失败，系统返回未批改，不会悄悄把学生记成答错。后续可以重试。

### 7. 为什么当前使用 JSON？

比赛部署是单进程、轻量容器，JSON 足够完成课程演示，也方便检查和迁移。我们用原子写入和线程锁保护修改。多用户生产环境需要换成数据库和更完整的身份认证，这属于下一阶段。

### 8. 用户自己填写模型地址安全吗？

用户端点只允许公开的 HTTP 或 HTTPS 地址，禁止回环、内网和云元数据地址。重定向目标也会再次检查。API key 只随模型请求发送，不写入路由遥测。

### 9. Compute Center 里的数据会永久保存吗？

当前遥测是进程内的有界记录，重启后会重置。这样做适合比赛中的实时证据展示。生产环境还需要数据库、保留周期和更完整的运维监控。

### 10. 你们如何证明节省了模型调用？

规则判定和题库复用会各自产生事件记录，Compute Center 会统计节省次数。我们不把所有请求都叫作“节省”，只统计确实没有发起模型调用的路径。

### 11. 如果评委现场网络或模型服务不可用怎么办？

先展示 Compute Center 的当前状态，再走客观题和题库路径。它们不依赖模型服务。主观题可以展示备用服务、未批改状态或失败后的重试，故障本身也能说明系统的降级设计。

### 12. 这个系统能扩展到多少课程和用户？

当前版本面向比赛演示和轻量课程，单进程 JSON 存储还没有面向大规模生产。扩展时需要把存储换成数据库，把遥测换成持久化服务，再增加任务队列和更完整的认证。核心路由接口可以保留。

## 临场应变

- 页面加载慢时，先讲当前页面的目的，不要连续点击。
- 模型服务失败时，直接说“现在进入未批改路径”，不要反复刷新。
- 评委追问 GPU 时，坚持说明“接口已留好，硬件尚未验收”。
- 时间只剩 3 分钟时，直接跳到第 9 页，完成客观题、主观题和故障演练中的两项，再回 Dashboard。
- 评委问到没有准备的指标时，不猜。回答“当前版本没有测这个指标，我们记录为后续验收项”。
